# Project context

- Local Tauri 2 app with Svelte 5 and a Rust backend. Linux AppImage and Windows x64 NSIS are the packaging targets. GitHub Actions builds are manual-only, with optional draft prereleases; Debian packaging is deferred. Windows desktop behavior requires validation.
- The app manages private yt-dlp and FFmpeg/ffprobe binaries instead of relying on user-installed tools or Python. Local setup downloads pinned builds and verifies SHA-256 checksums; desktop packages bundle the tools and Deno runtime.
- `npm run dev` starts Tauri and Vite. `npm run dev:web` serves only the frontend and cannot invoke Rust. Keep the Tauri JavaScript packages and Rust crates on matching major/minor versions.
- Search automatically detects URL input with a regex in Rust. Names/artists use yt-dlp `ytsearch1`; YouTube watch, short-link, Shorts, embed and live URLs are validated and normalized to one HTTPS video URL, dropping playlist/tracking parameters. Unsupported video links are rejected, and `--no-playlist` keeps resolution to a single video. Both paths return `{ id, title, channel }`; channel is optional metadata. The result card can be dismissed without affecting playback or queued downloads.
- YouTube previews resolve a temporary HTTPS audio URL, preferring M4A. Extraction is serialized, uses cancellation tickets, and has a 45-second deadline. Linux cancellation terminates the process group; stale tickets cannot cancel newer previews.
- The bundled Deno runtime is passed explicitly to yt-dlp for YouTube challenges. Playback still depends on the platform WebView and codecs.
- The library uses a native folder picker and lists direct, regular MP3 files only: case-insensitive extension, no recursion or symlinks. Filenames provide titles; the folder label shows its last two segments on one line. Selection lasts for the session.
- A debug-only `dev-library.local.json` can set `music_folder` to avoid repeated selection. It is excluded locally through `.git/info/exclude` and must not be committed.
- Library cards support play/pause and a right-click menu with Rename and Delete. Both actions use a confirmation/edit dialog; Rust validates the selected folder and file, preserves `.mp3` on rename, and prevents overwriting another file.
- Local playback now uses a Rust HTTP server bound to `127.0.0.1` on a dynamic port, with GET/HEAD and byte-range support. Random per-track URLs are revoked when discarded; requests validate that the MP3 remains in the selected folder. This replaced Blob playback after audible stuttering on Linux; the user confirmed the HTTP approach works. Windows remains untested.
- A single `Player.svelte` owns the audio element for both local tracks and YouTube previews; it sits at the bottom of the search column beside the full-height library. `player.service.ts` owns shared playback state, source loading, cancellation, and disposal, ensuring only one source plays at a time. Controls include play/pause, previous/next, shuffle, seeking, and volume.
- Library navigation resolves its queue from the current search results rather than a snapshot, so next/previous, shuffle and automatic advance stay within the visible tracks and do not reuse renamed or deleted paths. Changing the filter does not interrupt playback; if it excludes the active track, next starts at the first result, previous at the last, and shuffle chooses from the results. An empty result list does not advance. YouTube previews use a single-track queue. Failed source loads can be retried; replacing or destroying the player aborts pending loads and releases source resources. Temporary playback diagnostics were removed after testing.
- Downloads save MP3s into the selected folder, opening the same picker if needed. Filenames use the video title without its YouTube ID. Rust uses private FFmpeg, stages conversion, publishes without overwriting, and cleans temporary files. Filename collisions are reported after conversion; there is no ID-based duplicate index. One download runs at a time with a 10-minute deadline.
- A shared download queue decouples searching from downloading and reports live progress. Its summary sits at the bottom of the library and opens a floating list; failed items can be retried or removed. The queue disappears when all downloads finish successfully.
- Reusable operations and shared stores live in `src/lib/services/*.service.ts`. Components own presentation and audio-element bindings; shared playback orchestration belongs to the player service.
- Frontend styling uses Tailwind CSS through its Vite plugin. `ui/Popover.svelte` and `ui/Modal.svelte` share native overlay structures and accept injected `children`; callers provide content and interaction rules. Icons use bundled Iconify `andrsrxn` modules for offline use.
- All app buttons use `ui/Button.svelte` for shared theme variants, sizing, focus and disabled states. It forwards native button attributes/events, defaults to `type="button"`, and exposes `bind:element` for native DOM references used by popover positioning and focus restoration. Submit buttons explicitly set `type="submit"`. Selected library cards use a 5% primary tint rather than a solid secondary fill.
- Appearance uses shared light and soft dark surfaces, with neutral, cyan, indigo and pink primary colors. Each palette also defines its own secondary background/foreground using the original light/dark palette values. Accent, focus ring and two wave colors derive from the selected primary. The settings modal opens a palette popover; the footer toggles light/dark independently. `appearance.service.ts` keeps the controls in sync and persists `tunely.appearance` in localStorage. `static/theme-init.js` restores it before paint, with cyan/light as the fallback when saved data is missing, invalid or unavailable.
- Standard validation: `npm run check`, `npm run build`, Rust tests, and Rust formatting checks. Automated checks do not replace playback or platform-specific testing.
